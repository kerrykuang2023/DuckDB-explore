# duckdb-explore

## Actor
数据分析师 / 开发者（想直观理解 DuckDB 能力、不想写 SQL 的人）

## Goal
不用写 SQL，通过可视化界面全链路理解 DuckDB 的核心特性（联邦查询、跨源 JOIN、列式向量化、无 ETL、轻量嵌入式、性能），并能用真实数据验证这些特性确实成立。

## Action
在 UI 上选择数据源、点选字段和聚合操作、触发查询，看到 DuckDB 自动执行跨源联邦查询、返回结果并以图表展示，同时看到每条查询的耗时，从而直观对比 DuckDB 的引擎联邦能力。

## User story
As a 数据分析师，I want to 通过可视化界面（而非 SQL）连接多个数据源并触发 DuckDB 的联邦查询与跨源 JOIN，so that 我能直观理解 DuckDB 的引擎级联邦、列式向量化性能和无 ETL 特性，并对比它相比"LLM 编排联邦"的确定性优势。

## Business rules
- R-01 数据源联邦 — UI 能连接并展示多个异构数据源（SQLite / CSV / Parquet），用户可选任一数据源作为查询目标。
- R-02 跨源 JOIN — UI 能跨两个不同来源（如 SQLite 表 + CSV 维度表）做关联查询，用户通过点选指定关联键，无需手写 JOIN 语法。
- R-03 无 ETL 直查 — 直接读取外部文件/库，不要求用户先建表或导入数据。
- R-04 列式向量化性能可见 — 每次查询展示实际耗时（毫秒级），证明列式 + 向量化执行的分析性能。
- R-05 结果可视化 — 查询结果以表格 + 图表（柱状图/指标卡）呈现，而非只显示原始 SQL 文本。
- R-06 SQL 透明可查 — 虽不用用户写 SQL，但 UI 需展示 DuckDB 实际执行的 SQL（只读展示，供理解底层）。
- R-07 资源轻量提示 — UI 展示 DuckDB 为嵌入式、无 server、单进程轻量运行的说明（静态信息卡片）。
- R-08 单进程多线程读 — 演示 DuckDB 在单进程内完成多个查询，无需启动外部服务。

## Non-goals
- 不实现分布式横向扩展（DuckDB 单机嵌入式定位）
- 不实现高并发写入（DuckDB 单 writer）
- 不替换生产 OLTP 数据库
- 不做成通用 BI 平台
- 不集成 LLM（本阶段只验证 DuckDB 引擎能力，LLM 联邦对比留作后续用户故事）
